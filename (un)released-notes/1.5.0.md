### New Features
- [TWITCH] Added support for GIF message events;
- Community widgets and plugins can now be installed and updated from the Widgets and Plugins windows, with version selection;
  - Plugins installed from the community list load on the next start, with a notice to restart the app;
- Added new custom event window for testing purposes in the emulator;
- Added FontAwesome 5 provided in the widget assets;
- Added the `unichat:cheer` event for donations made with platform currencies (Twitch Bits and YouTube Jewels):
  - Default widget and activity feed now show cheer alerts;
  - Emulator can dispatch cheer events for testing;
- Implemented globally emulator events dispatch (to receive events emitted by the emulator in your OBS source for example);
  - All events dispatched by the emulator has a flag `unichat:emulator_generated` to identify them as emulator-generated events;
- Added warn messages to widgets;
- Added support for custom icons in scrapers (only `data:` URLs);
- Added MSI installer for Windows;
- Added currency conversion for donations, powered by [frankfurter.dev](https://frankfurter.dev/):
  - Pick a target currency under `Settings > General`, it is disabled by default;
  - YouTube Super Chats and Super Stickers are converted before the event is emitted, so widgets need no changes;
  - The scraped amount is kept in the new `originalValue` and `originalCurrency` fields of the donate event;
  - Plugins can convert values through the new `unichat:currency` module;
- Plugins can now emit cheer events through `UniChatEvent:Cheer{...}`;
- Added the `unichat:utils` module with `random_color_by_seed`;
- YouTube Jewels cheer events carry `cheerId`, `cheerTitle` and `cheerDescription`:
  - `cheerId` and `cheerTitle` are derived from the gift asset filename, so the title is an approximation of the real name;
  - `cheerDescription` carries the actual description, or `null` when it can't be read;
  - `value` is always `null`, as the amount of Jewels is not available;
- Added the `switch` field type, a checkbox shown as a switch;
- Widgets receive the `unichat:loaded` event when they load, with their field values, user store and target currency;
- Added the [`@voguh/unichat-api`](https://github.com/voguh/unichat/tree/main/unichat-api) package with the TypeScript and Lua type definitions for widgets and plugins;

### Event contract changes

Breaking for anyone typed against the previous contract. The YouTube and Twitch scrapers keep filling the same fields as before.

- Twitch Bits are now emitted as `unichat:cheer` instead of `unichat:donate`; `unichat:donate` is now used only for YouTube Super Chats and Super Stickers;
- `authorType` is no longer nullable on raid and redemption events;
- `raid.authorId` is no longer nullable. On YouTube it holds a temporary value, as the raid banner carries no channel id;
- `redemption.rewardIconUrl` is now nullable;
- Twitch tags already mapped to event fields (badges, color, emotes, `msg-param-*`, etc.) are no longer copied into the `unichat:raw:twitch:*` flags;
- Fixed the Lua type definitions: `UniChatEvent:Other` is really `UniChatEvent:Custom`, `raid.viewer_count` is really `viewerCount`, and `clear.platform` had the wrong type;
- Added the missing `UniChatEventUserstoreUpdate` and `UniChatEventCustom` TypeScript interfaces;

### Plugin changes
- Plugins are now identified by their folder name; the manifest `name` is only the display name:
  - `__PLUGIN_NAME` now holds the plugin folder name;
  - `dependencies` now reference plugin folder names;
- Events received by plugins are now read-only;
- Plugin scrapers can no longer emit events for the Twitch and YouTube platforms, nor `unichat:userstore_update` events;
- `unichat:http` no longer raises an error for non-2xx responses; check `ok` or `status_code` instead;
